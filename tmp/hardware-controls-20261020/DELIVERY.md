# 相机列表、启动采集与共享光源串口修正（2026-10-20）

已完成最小源码修正，隔离产物位于 `build-delivery`。未部署、未制作安装包，未打开完整主程序，真实相机、光源控制器和 IO 仍需现场验收。

## 根因与证据

1. **右侧相机列表为空使光源操作被禁用。** 原代码仅在 `InitCam → ProcessInitCamStatus` 中填充 `cbDeviceList` 及物理相机/工位索引表；上轮新机默认 `bAutoConnCam=false` 后跳过此链。手动 `TryConnectCameras` 虽可完成相机连接，但只保留局部 `latestItems`，没有更新主界面 `items` 和右侧列表。`TryGetSelectedCameraBinding` 因无选项返回 false，`RefreshSelectedCameraLightUI` 因而禁用亮度、通道、同步及工具栏开关。连接串口无法补齐相机选择，因此看起来无论怎么连接都无法使用。
2. **关闭自动连接却仍启动采集。** 启动时 `SearchCam` 可以枚举到两台相机，但 `InitCam` 受自动连接开关控制；后面的 `StartGrab()` 却无条件遍历枚举数量。此时主界面 `camera2=null`（日志显示长度0），内部固定容量数组尚无已初始化对象，`_cameraCount=0`。`HIKVisionCamera.StartGrabbing(index)` 在调用原生 SDK 前的边界检查抛出异常，并非 SDK Start 返回失败，也不能由此判断带宽、触发设置或相机故障。用户截图中两条启动错误为 **14:56:15**，后来的手动连接成功为 **14:56:39**，属于不同阶段。
3. **所有重复 COM 被一律拒绝。** `SerialPortBinding.TryResolve` 原来将四槽任意重复解析到同一 COM 都判为冲突；参数窗口与实际打开/重连共用此验证。仅放宽验证还不够：原来各槽分别创建并打开 `SerialPort`，共享 COM 会发生重复打开；四通道命令还可能被另一面的独立旧状态覆盖。

## 修改范围及行为

业务代码仅涉及三个文件，保留上轮路径、授权及设备身份绑定改造。

- `VisionApplication/FrmMainUI.cs`：抽出 `RefreshCameraSelectionItems`，搜索、参数确认、手动连接和自动重连后刷新右侧列表，同时保留所选工位；曝光继续使用物理相机索引，光源继续使用对应工位/串口槽。A/B/同步采集选择不新增切换相机行为。列表刷新只更新 UI，不发送光源命令。
- `VisionApplication/FrmMainUI.cs`：启动采集遵守自动连接开关；批量 Start 仅访问已启用、索引有效、对象存在且缓冲就绪的工位，每台物理相机只启动一次。无效工位记录原因并跳过，不清理另一台已正常工作的相机。
- `CommonCls/SerialPortBinding.cs`：前三个光源槽允许解析到同一个 COM；第4槽 IO 与任一启用光源槽冲突仍拒绝。身份缺失、匹配不唯一、设备未连接或只有旧序号仍拒绝，不回退其他端口。参数窗口自动使用此规则，无需修改 Designer 或增加配置项。
- `VisionApplication/FrmMainUI.cs`：首次打开与重连共用 `OpenBoundSerialPort`，同一物理光源端口共用一个对象，不重复打开或关闭。断开时每个物理端口只关闭、释放一次，并清除全部别名。
- `VisionApplication/FrmMainUIExtention.cs`：共享控制器使用同一套四通道状态和亮度。初始化以该端口**最前面的已启用光源槽**参数为准，只初始化一次；成功后同步共享槽的亮度保存值。切换相机后调整某通道不会用另一份旧参数覆盖其他通道。发送失败不提交新亮度或开关状态。

同一个控制器的 CH1～CH4 是共同的物理通道；若两面分别接不同通道，分别选择对应通道操作。选中相同通道时操作的是同一路输出；光源“同步”仍作用于该控制器全部四通道，与 A/B/同步采集选择独立。不同 COM 的光源控制器保持独立参数和状态。

未修改相机 SDK 参数设置、图像取帧/转换/采集线程、IO 报文/解析/输出协议、授权、工程引用、Designer、配置、实际模型或 VPP。`PROJECT_CONTEXT.md` 已更新本轮原因、行为和验证边界。`changes.diff` 为相对于本轮开始快照的三文件差异，避免与上轮未提交改造混淆。

## 现场验收步骤

1. 按正常交付方式使用本批匹配的主程序及依赖，不覆盖现场配置、模型或工作区 VPP。本目录包含测试程序/源码/PDB和诊断文件，不是可直接整目录安装的部署包。
2. 自动连接关闭，保存启用的 A/B 工位与各自相机绑定，重启。确认启动不再对未初始化 Cam0/1 报 StartGrabbing 索引异常；手动连接相机后右侧列表显示两台，选 B 后再次连接/刷新仍选 B。取图、实际预览和曝光调节分别验收。
3. 先用两路不同 COM：配置并启用光源槽、连接串口，分别选择 A/B 相机，确认光源控件可用且调节对应控制器。串口未启用、未连接或写入失败时，确认不保存新亮度或伪报开关成功。
4. 再将 A/B 光源槽明确绑定同一个光源控制器 COM，IO 保持另一 COM。确认参数能保存、端口只打开一次；核对共享控制器初始化采用最前启用槽的四通道值。A 选择 CH1、B 选择 CH2，交替调节和开关，确认另一通道保持；选同一 CH 确认共用状态；光源同步只控制该控制器 CH1～CH4。断开/重新连接后重复确认。
5. 尝试让已启用 IO 槽与光源共用同一 COM，确认拒绝保存/连接。单独验证 IO 通信及物理输出；本轮未改协议。换 COM、设备缺失和身份歧义继续按原规则验收。
